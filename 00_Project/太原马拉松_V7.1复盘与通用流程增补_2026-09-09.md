## 做对的事情

- 坚持 TrailPrint3D 为路线、裁切范围和城市空间关系的核心事实入口；历史 GPX 没有冒充 2026 官方路线，而是明确作为纪念品效率优先的可复用输入。
- 路网没有机械采用“越多越真实”：经历过密、过稀后，以同尺寸已发布作品为对照选择中等层级，并冻结原始 OSM/GPX。
- 汾河先以 OSM multipolygon 恢复事实水面；因为它与赛道关系明确，且默认 100 mm 表达出现窄、碎和蓝色刀路不连续，才进入“主水系视觉强化”可选分支。强化后的河面、道路裁切、桥梁、红色轨迹和岸别约束作为一组同步派生关系。
- 桥梁识别从单一 `bridge` 标签升级为标签、跨越两岸和道路足迹三路证据；同时删除北端因轨迹投影造成的假跨河桥。
- 地标同时满足赛事终点联系、空间净距和 0.4 mm 制造识别度；Tripo 原件只作输入，另生成闭合制造候选。
- 底部只取官方奖牌剪纸马；用户确认 PNG 后按 Alpha 机械嵌入，未用生成式近似图或基础几何重画。
- 四件同盘没有误当成逐件可打印；目标机型碰撞不通过后，工程持久化为强制逐层。

## 主要失败与通用修正

| 现象 | 根因 | 通用修正 |
|---|---|---|
| 汾河最初太窄、碎裂 | 地形采样与共面涂色不足以表达城市主河 | 仅当水系与赛事/城市强相关、真实尺寸表达失败且事实输入充分时，进入有记录的视觉强化分支 |
| 河面加宽后路线/道路错位 | 只改变水面，未同步关联要素 | 水系强化必须触发水面、道路、桥梁、轨迹四项同步回归 |
| 自动桥梁漏桥或出现假桥 | OSM 标签不完整，单点投影会跨岸 | 标签＋横穿两岸＋道路足迹联合识别，并锁定原 GPX 岸别 |
| 底纹碎成 29 个组件 | 已确认图片再次按亮度阈值解释 | 有有效 Alpha 时必须 `alpha_only`，比较 PNG 与生产轮廓连通性 |
| R3 缺少六个磁孔 | 设计 Blend 有孔，制造底座来自无孔分支 | 磁孔必须在最终底座 STL 和最终主 3MF 内逐孔回读 |
| 最终 R3 没有同版本 Blend | STL/3MF 流水线完成后未反向保存装配 | 最终 3MF 确定性重建同版本 Blend，并生成顶、侧、底三视图 |
| 底图马倒置且无孔 | 未先建立最终几何底视事实图 | 图像生成只做摄影外观，功能与方向必须来自 Blender 真值图 |
| 3MF 替换工具遇到紧凑 XML 失败 | 工具假定固定缩进和完整 matrix 元数据 | XML 解析不得依赖缩进；可选元数据缺失时显式使用身份变换 |

## 沉淀到 V7.2 通用流程的新增门禁

1. **水系分支门**：主干默认保持原始水系；只有“赛事/城市强相关＋100 mm 表达失败＋事实输入充分”同时成立才允许强化。进入后同步重验道路裁切、全部桥梁、路线岸别与平滑，满足退出条件后返回主干。
2. **最终功能回读门**：磁孔、底纹、承座和文字在最终 STL 与最终 3MF 各检查一次。
3. **同版本 Blender 门**：从最终 3MF 的真实网格、材料子件和装配变换确定性重建，不重新设计；Blend、3MF、截图版本一致。
4. **三视图真值门**：顶视检查地图，侧视检查高度与装配，正底视检查图案方向及全部磁孔；黑色底座另出检查伪色图。
5. **生成图边界**：模拟实拍只能在三视图 PASS 后生成，不得增加、删除、镜像或重画功能结构。
6. **数字完工边界**：结构、3MF 和 GUI 切片通过后仅为 `DIGITAL_COMPLETE / PRINT_TEST_REQUIRED`；真机验证后才能封板。
