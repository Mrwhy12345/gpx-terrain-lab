# GPX 徒步沙盘生成系统：产品目标

更新日期：2026-07-28  
阶段：从单个作品升级为对外系统

## 一句话目标

用户上传一个 GPX 徒步轨迹文件，系统经过地形获取、GIS 处理、地图核验和可打印
几何生成，输出四个职责独立、保持同一装配坐标的多色 3MF：

1. `01_Terrain.3mf`：沙盘地形、地貌分色及水体安装槽；
2. `02_Base.3mf`：底座、定位结构、磁铁孔和纪念文字；
3. `03_Trail.3mf`：独立徒步轨迹及起终点。
4. `04_Water.3mf`：独立水体安装件。

## 产品价值

市场上常见方案重点是“GPX 变成一条凸起路线”或“生成一块地形”。本系统的差异
在于把以下环节连接起来：

`GPX → DEM/OSM → QGIS空间处理 → 国内地图人工核验 → Blender可制造几何
→ 多色分件3MF → 打印质量报告`

核心价值：

- **可信**：路线、水体和模型边界有数据来源及核验记录；
- **适合中国路线**：明确处理 WGS 84 与国内在线地图显示坐标的差异；
- **可制造**：不是只输出预览或 STL，而是输出已分件、同坐标、多色友好的 3MF；
- **可讲述**：底座自动加入路线名、日期、距离和起终点；
- **可复现**：每次生成都附参数、数据来源、假设和 QA 报告。

## 输入

### MVP 必需输入

- 一个 `.gpx` 文件。

### 系统自动推导

- 轨迹点、轨迹段、距离和异常跳点；
- 路线中心、范围和默认模型边界；
- 文件名或 GPX 名称中的路线名；
- GPX 时间中的日期；
- 默认 100 mm 六边形模板；
- 默认打印配置和颜色角色。

### 可选参数

- 路线显示名、日期；
- 模型尺寸和形状；
- 垂直比例；
- 水体、村庄等要素开关；
- 底座、磁铁孔和文字开关；
- 打印机、喷嘴、耗材槽与颜色。

若 GPX 不含名称或时间，系统使用文件名和生成日期，并在预览页允许修改。这样核心
入口仍然只有 GPX，不把产品变成复杂 GIS 表单。

## 输出

### 四个正式 3MF

| 文件 | 内容 | 要求 |
|---|---|---|
| `01_Terrain.3mf` | 地形、选定地貌分区和水体安装槽 | 多色部件、无负 Z、可独立打印 |
| `02_Base.3mf` | 底座、凹槽、磁铁孔、文字 | 自动居中、平放打印板 |
| `03_Trail.3mf` | 轨迹、起终点 | 与地形保持同一 XY 坐标 |
| `04_Water.3mf` | 水体独立安装件 | 蓝色、底面可平放、与安装槽匹配 |

### 附属交付

- 俯视预览和斜视预览；
- 与正式打印文件版本一致的 Blender 设计预览项目；
- 数据来源与参数 JSON；
- 几何和 3MF QA 报告；
- SHA-256 校验和；
- OSM attribution 文本；
- 未通过自动判断时的人工核验清单。

正式 `final/` 目录只包含两类用户交付：用于打印的 3MF，以及用于设计预览的
Blender 项目。过程报告、截图、候选和中间几何保留在各自工作目录。

## 推荐产品流程

1. **上传与预检**
   - 解析 GPX；
   - 检查轨迹点、距离、时间和异常跳点；
   - 显示隐私提示和预计处理范围。
2. **地理数据准备**
   - 获取合法授权的 DEM；
   - 获取并保存 OSM 原始响应；
   - 使用 QGIS Processing 完成投影、裁切和空间分析。
3. **核验**
   - 在高德 JS API 页面显示轨迹和候选矢量；
   - 只把高德作为在线视觉核对界面；
   - 用户确认保留/简化/排除；
   - 不抓取、缓存或把高德影像作为模型纹理/数据源。
4. **模型生成**
   - Blender 后台生成地形、水体、轨迹和底座；
   - 根据最终基座 Mesh 自动居中文字；
   - 生成同坐标独立零件。
5. **3MF 封装**
   - 写入耗材映射、对象变换和项目设置；
   - 输出四个版本一致、职责独立的 3MF。
6. **自动 QA**
   - 检查负 Z、非流形边、零件数、最小特征、ZIP 和哈希；
   - 生成俯视图、斜视图和风险清单。
7. **下载**
   - 用户下载四个 3MF 和生成报告。

### 已有能力

- GPX 解析、距离和异常检查；
- OSM 水体获取与空间筛选；
- 精确模型边界提取；
- GeoJSON/GeoPackage 输出；
- 高德在线叠加核验页面；
- Blender 后台地形、水体、轨迹、底座和文字生成；

## 推荐系统形态

### 第一阶段：本地优先的 Web 工作台

- 浏览器负责上传、预览、核验和下载；
- 本机 Worker 调用 QGIS 和 Blender；
- GPX 与中间地理数据默认不离开用户电脑；
- 先服务少量用户和定制订单。

这样可以降低服务器 GPU/CPU 成本、GPX 隐私风险和 Blender/QGIS 部署复杂度。

### 第二阶段：托管生成服务

- API/队列接收任务；
- 独立 QGIS Worker 和 Blender Worker；
- 对象存储保存有限时间的输入输出；
- 支持并发、重试、配额和付费。

只有在本地工作台用多条路线验证稳定后，才进入托管 SaaS。

## 高德使用边界

- 高德承担“浏览器中的人工视觉核对”，不承担模型地形或水体数据生产；
- GPX 的 WGS 84 坐标只为在线显示转换到高德所需坐标；
- 不抓取、下载、缓存或分发卫星影像；
- 不把高德截图、瓦片或内部数据打包进 3MF；
- 对外上线前，需要按实际商业模式再次核对高德平台协议和授权。

## MVP 验收标准

用至少 5 条不同地貌 GPX 完成测试，其中至少 3 条完成实体打印：

- 用户只上传 GPX 即可进入预览；
- 任务失败可定位到明确阶段并重试；
- 四个 3MF 文件自动生成且版本一致；
- 四个文件在目标切片器中保持正确装配；
- 无负 Z、无退化/非流形打印零件；
- 主要轨迹和水体通过逐层预览；
- 基座文字自动居中；
- 每次生成都有参数和数据来源报告；
- 原始 GPX 可按用户操作或期限删除；
- 不依赖修改代码完成新路线。

## 不进入首个 MVP

- 卫星影像纹理打印；
- 全自动替代人工水体判断；
- 森林、全部道路、建筑和等高线同时开启；
- 多图块大型地图；
- 所有品牌切片器的项目文件兼容；
- 无限制模型尺寸和任意底座结构；
- 手机端完整 3D 编辑器。

## 阶段路线

### P0：S02 真机验收

- 完成 V010 实体检查；
- 记录打印参数、时间、耗材和缺陷；
- 固化第一张打印参数卡。

### P1：参数化核心

- 消除脚本中的 S02 专用路径、名称和 OSM ID；
- 定义统一 `job.json`；
- 一个命令执行 GPX 预检到四个 3MF；
- 失败可从阶段 checkpoint 恢复。

### P2：本地工作台

- 上传 GPX；
- 任务进度；
- 地图候选核验；
- 模型预览；
- 下载四个 3MF 和报告。

### P3：跨路线验证

- 5 条 GPX 自动生成；
- 3 次实体打印；
- 建立路线宽度、水体宽度、垂直比例和尺寸参数表。

### P4：对外试用

- 用户协议、隐私、归属和地图服务审查；
- 错误监控和支持流程；
- 小规模邀请测试；
- 根据失败类型决定是否建设托管服务。

## 产品成功指标

- 新 GPX 无需改代码即可生成；
- 从上传到预览的人工操作不超过 5 分钟；
- 80% 以上任务无需开发者介入；
- 3MF 自动 QA 通过率达到 90%；
- 首次实体打印可接受率达到 80%；
- 每个失败都能归类到数据、GIS、几何、3MF 或打印阶段；
- 第二条路线的制作 token 和人工时间低于 S02 的 30%。
