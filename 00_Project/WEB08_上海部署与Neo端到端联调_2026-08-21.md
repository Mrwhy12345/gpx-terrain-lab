# WEB08 上海部署与 Neo 端到端联调

日期：2026-08-21

## 阶段目标

1. 将 WebApp 部署到上海服务器；
2. 由上海 Web 通过安全通道调用 Neo 的 TrailPrint3D / Blender 后端；
3. 使用真实 GPX 实时生成 5 个 3MF 和 1 个 Blender，并从上海入口下载；
4. 为后续将计算后端迁移到 Mac mini 固化部署边界。

## 本轮发现并修复

第一版上海代理会先把整个下载读入内存，并使用 30 秒上游超时。约 200 MB 的交付包可能因此无法下载。已改为 1 MiB 分块流式转发，并将上游超时参数化为 600 秒。客户端现在能收到原始 `Content-Length` 和 `Content-Disposition`。

公网 HTTP 回归还发现 `crypto.randomUUID()` 只在安全上下文可用：localhost 正常，但 `http://IP:4173` 会在初始化匿名客户 ID 时终止全部前端脚本，表现为页面可见、选择 GPX 无反应。已加入 RFC 4122 v4 兼容生成器。公网浏览器复测成功读取星溪 GPX（878 点、9.52 km），生成按钮已启用。

ZIP 对本项目主要承担整体交付容器作用。3MF 本身已经是压缩容器，Blend 也很难再次显著压缩，因此后续应采用 ZIP `store` 模式降低打包 CPU，并保留六个文件的独立下载。

## 当前限制与下一步

- 上海 Web 进程与 Neo SSH 隧道仍是本次会话启动的临时常驻方式，重启恢复尚未正式验收；
- `webapp` 当前无 linger，正式 systemd user service 需要管理员开启 linger，或由系统级服务托管；
- 4173 为临时公网端口，不是正式生产入口；
- 约 200 MB 文件经反向隧道传输速度有限，正式方案应将最终产物推送到对象存储，由上海返回鉴权下载地址；
- Mac mini 迁移待定：安装依赖、同步代码、迁移 Worker、建立反向隧道、真实 GPX 回归、下载验收。
