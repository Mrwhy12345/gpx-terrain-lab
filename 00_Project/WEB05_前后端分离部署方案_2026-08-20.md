# WEB05｜前后端分离部署方案

日期：2026-08-20
阶段目标：先在 Mac mini 完成可运行的前后端分离，再将前端平移到上海服务器。

## 1. 产品边界

- 前端只负责：GPX 上传、参数编辑、创意输入、任务状态、三机位预览与成果下载。
- 后端只负责：GPX 落盘、任务编排、TrailPrint3D、Blender、3MF 封装、Bambu 兼容性 QA、成果清单。
- Mac mini Worker 只负责重计算，不承担公网用户页面。
- 原始 GPX 和不同任务的成果不得跨任务复用。

## 2. 两阶段架构

### 阶段 A：Mac mini 本地验收

```text
浏览器
  └─ http://127.0.0.1:4173  前端静态服务
       └─ http://127.0.0.1:4174  后端 API
            ├─ 08_Jobs/ 任务与成果
            ├─ TrailPrint3D / Blender
            └─ 3MF / Bambu QA
```

- 前端端口：`4173`
- 后端端口：`4174`
- API 地址由运行时配置提供，禁止写死在构建产物中。
- 保留当前单体 `4173` 入口作为短期回退，不覆盖历史任务。

### 阶段 B：上海服务器 + Mac mini Worker

```text
客户浏览器
  └─ 上海服务器：Web + 公共 API + 任务数据库 + 对象存储
       ├─ 写入待处理任务
       ├─ 展示状态和预览
       └─ 提供 5+1 下载
              ↑ 成果上传
              │
       Mac mini Worker 主动轮询/领取任务
              ├─ 下载 GPX 与参数
              ├─ TrailPrint3D / Blender / 3MF
              ├─ Bambu 兼容性 QA
              └─ 上传结果与报告
```

正式阶段不让浏览器直接访问 Mac mini，也不将 Blender API 裸露到公网。Mac mini
主动向上海服务器发起出站 HTTPS 请求，可以适应家庭网络、动态 IP 和 NAT。

## 3. API 最小契约

- `GET /api/health`：服务、Blender、流水线版本与存储可写状态。
- `POST /api/jobs`：创建任务，返回 `job_id`。
- `GET /api/jobs/{job_id}`：返回排队、运行阶段、失败原因或完成状态。
- `POST /api/jobs/{job_id}/finalize`：进入最终 5+1 生产；本地阶段可保留同步兼容入口。
- `GET /api/jobs/{job_id}/manifest`：文件、SHA-256、QA 和下载地址。
- `GET /generated/...`：预览图。
- `GET /downloads/...`：交付文件。

## 3.1 已实现的异步任务状态机

```text
提交 GPX → QUEUED → RUNNING → PREVIEW_READY
                              └→ 提交最终生产 → QUEUED → RUNNING → FINAL_READY
                  任一阶段异常 → FAILED（保留错误与日志）
```

- `POST /api/generate-preview` 与 `POST /api/finalize-job` 均立即返回 `202 + job_id`；
- 浏览器每 2 秒轮询 `GET /api/jobs/{job_id}`，关闭页面不会终止后台任务；
- Mac mini 当前使用单 Worker 串行执行，避免多个 Blender 同时争抢内存和 GPU；
- 状态原子写入每个任务的 `review/web_task_status.json`；
- 服务重启后自动恢复处于 `QUEUED / RUNNING` 的任务；
- 重复点击最终生成不会重复启动同一任务。
- 前端使用本机 `localStorage` 保存活动任务号，刷新页面后继续轮询；活动任务期间锁定 GPX 与提交按钮，并展示任务收据。
- 后端以“GPX 内容 + 全部任务参数”的 SHA-256 作为幂等指纹；相同输入仍在排队、运行或等待最终生成时，返回原任务而不新建。

当前实现版本：`WEB05_ASYNC_V2_QUEUE`。

透明队列仅公开 Worker 数量、排队总数、本人前方任务数和本人计算阶段；不公开其他用户的 GPX 文件名、路线标题、参数或成果地址。正式公网多用户版还必须增加用户鉴权、任务所有权校验和下载签名，本地版的任务号不能视为安全凭证。

## 5. 今天的验收标准

1. `4173` 仅提供前端文件；停止后端时页面仍可打开并明确显示后端离线。
2. `4174` 仅提供 API、预览与下载，不提供前端页面。
3. 前端 API 地址可通过配置切换，不修改业务代码。
4. `/api/health` 返回代码版本、底座算法版本、字体算法版本和 Blender 可用性。
5. 一键脚本支持 `start / stop / restart / status`，记录 PID 与日志并检测端口冲突。
6. 使用一份两步路 GPX 完成：上传 → 仿真 → 最终 5+1 → 下载。
7. 任务目录、GPX SHA-256、QA 与下载成果同源。

## 5.1 本地启动与检查

```bash
python3 09_WebApp/manage_split.py start
python3 09_WebApp/manage_split.py status
python3 09_WebApp/manage_split.py restart
python3 09_WebApp/manage_split.py stop
```

- 前端日志：`09_WebApp/runtime/frontend.log`
- 后端日志：`09_WebApp/runtime/backend.log`
- PID 清单：`09_WebApp/runtime/split_services.json`
- 前端 API 配置：`09_WebApp/local/config.js`

## 6. Bambu 验证口径

当前自动化能够完成 3MF 封装、颜色/对象层级、ZIP、尺寸、Z 和几何门禁；只有实际调用
Bambu Studio 切片引擎并产生切片结果时，才称为“Bambu 切片验证”。未调用切片引擎的
阶段统一称为“Bambu 兼容性 QA”，避免把 3MF 结构检查表述成真切片。

## 7. 上海迁移前的安全项

- HTTPS、任务鉴权、上传大小限制、GPX XML 安全解析；
- 下载链接限时签名；
- Worker 凭证与客户凭证分离；
- 任务幂等键、超时、取消、重试和死信状态；
- GPX、日志、预览和成果的保存期限与删除策略；
- Mac mini 不开放 Blender、SSH 或文件系统公网端口。
