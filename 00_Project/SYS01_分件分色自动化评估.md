日期：2026-07-28  
评估对象：现有 S02 工具链  
原评估目标：沙盘、底座、轨迹三个 3MF

> 2026-07-28 需求变更：SYS01_V002 将水体升级为第四个独立安装件。本文件保留
> V001 三文件评估的历史事实；当前产品契约以
> `00_Project/对外系统目标.md` 和 V002 复核记录为准。

## 🦁 总结论

**能实现，但当前属于“案例级半自动化”，还不是“任意 GPX 一键自动化”。**

- 对 S02 已知 Blender 场景重复生成：约 80%～90% 自动化；
- 对一条新的 GPX：约 40%～50% 自动化；
- 当前自动化成熟度：3/5；
- 分件几何和耗材映射已经验证；
- 统一配置、纯净三文件封装、任务编排和切片层 QA 尚未完成。

## 目标文件契约

### `01_Terrain.3mf`

只允许包含：

1. 低地绿色；
2. 中段/村庄棕色；
3. 高地灰色；
4. 水体蓝色。

### `02_Base.3mf`

只允许包含：

1. 灰色底座；
2. 棕色文字。

### `03_Trail.3mf`

只允许包含：

1. 红色轨迹及起终点。

三个文件必须使用同一模型坐标契约，且不得在不同文件中重复放入可打印参考件。

## 🐒 数据与分色要素

| 能力 | 当前状态 | 自动化判断 |
|---|---|---|
| GPX解析、距离、异常点 | 已有脚本 | 可自动 |
| OSM水体获取与落盘 | 已有probe和重试 | 可自动 |
| 距轨迹与边界筛选 | 已有脚本 | 可自动 |
| 水体保留/简化/排除 | 已有规则 | 可自动初筛，需人工确认 |
| 模型边界裁切 | 已有脚本 | 可自动 |
| 高德核验 | 已有页面 | 人在回路 |
| DEM与地形来源 | 已在TrailPrint3D案例验证 | 尚未形成统一服务适配 |

结论：空间数据能够生成分色输入，但“高德视觉核验”和部分数据语义不能在 MVP
中完全取消人工判断。

## 🐗 Blender分件能力

现有工具已经能根据语义标签识别和导出：

- `TERRAIN_LOW_GREEN`；
- `TERRAIN_MIDDLE_BROWN`；
- `TERRAIN_HIGH_GRAY`；
- `stream_ribbon` / `water_area`；
- `residential_areas_printable`；
- `trail_insert`；
- `display_base`；
- `display_title`。

`export_three_physical_pieces.py` 已实际输出：

- 底座：灰色底座 + 棕色文字；
- 沙盘：绿色低地 + 棕色中段/村庄 + 灰色高地 + 蓝色水体；
- 轨迹：独立红色嵌件。

所有报告中的上述零件非流形边均为 0。说明“按对象分件”和“按颜色分组”已经
实现，不需要重新发明几何算法。

## 🐾 自动化工具链

### 已有

- 40 个 Python 工具；
- 28 个工具已有命令行参数或 Blender 参数入口；
- 水体、道路、村庄、轨迹、底座、文字均有专项脚本；
- STL 分件导出已有报告；
- 3MF 零件替换、耗材设置和项目设置复制已有工具；
- 成功数据已经支持本地 checkpoint 恢复。

### 缺口

- 29 个工具仍出现 `S02`、`Xingxi` 或“星溪”等案例专用标识；
- 没有统一 `job.json`；
- 没有单一 orchestrator 串联所有阶段；
- 多个脚本使用 `next(...)` 强制假定水体、村庄、底座等对象一定存在；
- 文字内容仍在脚本常量中；
- 失败没有统一错误码和阶段状态；
- 3MF 封装由多个脚本和外部 Bambu Studio 操作拼接；
- 尚不能一条命令从 GPX 直接生成三个最终 3MF。

### 新发现

`V010_02_Terrain_ThreeBand_Water.3mf` 实际有两个可打印顶层对象：

1. 一个红色轨迹参考/单独打印对象；
2. 一个包含绿、棕、灰、蓝四个零件的沙盘装配。

其 `model_settings.config` 中沙盘装配的四个颜色零件耗材为1/2/3/4，但同一
3MF还保留了轨迹对象；轨迹同时又存在于
`V010_03_Trail_Red.3mf`。

这不否定 S02 打印能力，但不满足新系统的“文件职责纯净”契约。产品化封装器必须
移除沙盘文件中的参考轨迹，只保留四个沙盘分色零件。

## 自动化等级

| 等级 | 定义 | 当前 |
|---:|---|---|
| 1 | 手工建模和导出 | 已超过 |
| 2 | 单步脚本，可复现部分任务 | 已超过 |
| 3 | 已知案例可重复生成，有人工串联 | **当前** |
| 4 | 新GPX由统一配置驱动，一键生成并自动QA | SYS01目标 |
| 5 | 多用户任务队列、失败恢复、跨版本回归 | 对外系统成熟期 |

## 升级到等级4所需工作

### P1：统一任务配置

建立：

- `job.schema.json`
- `job.json`
- 颜色角色、尺寸、文字、数据源和输出文件契约。

### P2：场景语义契约

以稳定语义标签识别对象，不依赖 `S02_*` 名称；允许水体、村庄等可选对象为空。

### P3：统一分件清单

Blender 输出 `parts_manifest.json`：

- 文件角色；
- 零件角色；
- 颜色/耗材；
- 坐标原点；
- 包围盒；
- 面数和非流形边。

### P4：纯净3MF封装

按 manifest 分别创建三个 3MF：

- 沙盘只能包含 terrain 角色；
- 底座只能包含 base/title 角色；
- 轨迹只能包含 trail 角色；
- 禁止参考件进入其他文件的 printable build。

### P5：自动QA

增加以下硬门槛：

- 精确3文件；
- 每个文件的允许角色白名单；
- 不同文件间的重复网格检查；
- 耗材映射；
- 坐标契约；
- 负Z；
- 非流形边；
- ZIP；
- SHA-256；
- 切片连续性风险。

### P6：统一编排

实现：

`prepare → gis → review → blender → export → package → qa`

每阶段幂等、可重试并记录 checkpoint。

## 最终判断

现有工具链已经证明：

> 沙盘可以自动分成绿色、棕色、灰色和蓝色实体，底座可以分成灰色与棕色，
> 轨迹可以作为独立红色零件，并可写入多色3MF。

尚未证明：

> 任意新GPX无需改代码，即可一键、无人工串联地生成职责纯净的三个3MF。

因此 SYS01 不需要重新研究“能不能分件分色”，而应集中解决“如何参数化、编排、
封装纯净和自动验收”。
