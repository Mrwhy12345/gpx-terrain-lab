## 目标

把已经通过真机验证的 GPX 沙盘经验做成可视化本地入口，降低 TrailPrint3D 参数填写成本，并为 Bambu Studio 交付建立统一任务配置。

## 不可变事实

- 客户输入是一份 GPX；
- 工程数据中的地形、水、森林、城市等来自 TrailPrint3D；
- 当前真机基线为 100 mm、Resolution 8、Elevation Scale 1.80、Path Thickness 1.60 mm、Path Scale 0.80；
- 标准交付是 5 个 3MF 和 1 个 Blender 项目；
- 原始 GPX 不覆盖、不上传。

## 本阶段决定

- 先交付零依赖静态本地页面，避免前端依赖下载阻塞本地使用；
- 页面只暴露客户真正需要调整的参数，默认值来自真机基线；
- 使用“上传—工程—创意—输出”的阶段导航；
- 用实时沙盘示意、配色图例、参数偏差提示和输出清单降低误操作；
- 快速草模只表达当前 GPX 平面形状，明确标注非最终渲染；
- 真实预览必须由同一份任务参数驱动 TrailPrint3D 与 Blender 后回传；
- WEB01.1 接通真实仿真，但不伪装成已经完成最终 5+1 文件生成。

## WEB01.2 多机位与交付覆盖

- 一次 Blender 仿真固定输出装配透视、顶视关系、侧视高度三个机位；
- 增加与地形同轴的六边形灰色装配参考底座，避免“无底座”的错误观感；
- 参考底座只表达包络和装配位置，不冒充带文字、Logo 和安装细节的最终打印件；
- 页面新增缩略图切换与六项交付物覆盖状态，明确 `ready / reference / pending`；
- 三机位数字边界：参考底座 XY `110 × 95.26 mm`，地形 XY `100 × 86.60 mm`，中心对齐。
- 用户输入前即预留三个机位和六项交付物槽位，状态从“等待”原位转换为仿真、QA 与下载，减少布局跳变并提前建立交付预期。

## WEB01.3 单一流程交互

- 参考 `ecofengyoojing.com` 的核心交互模型：实时预览持续存在、任一时刻只编辑一个步骤、底部只有一个流程出口；
- 删除上传卡片中的第二个“下一步”，避免局部按钮与全局向导竞争；
- 顶部步骤仅承担进度与回跳，未上传 GPX 时禁止越级；
- 工程、创意、输出内容按当前步骤互斥显示，不再把四个阶段同时铺成一张长表单；
- 固定底部操作栏成为唯一的“上一步 / 下一步”，输出阶段则改为明确的 Blender 仿真与成果操作。

## WEB01.4 底座文字仿真

- 底座参考体新增标题、日期与 `Resolution/尺寸` 三边文字；
- 使用系统中文字体 `STHeiti Medium.ttc`，避免浏览器仿真与 Blender 中文乱码；
- 文字位置跟随六边形边框的参数坐标，顶视与装配透视均可验收；
- 当前仍属于参考底座文字，最终打印字体实体、底部 Logo 和 3MF 必须由完整流水线复核。

## WEB01.5 最终文件与下载闭环

- 新增 `/api/finalize-job`：把同一 Web 仿真任务转成最终交付，不覆盖真机基准或原始 GPX；
- 星溪线以 GPX SHA-256、标题、日期、尺寸、R8、高程 1.80、轨迹宽 1.60 和完整水网八项严格匹配真机验证基准；
- 匹配后复制 5 个 3MF 与 1 个 Blender 到该 Web 任务的 `final/`，逐件生成 SHA-256，并打包为完整 ZIP；
- 3MF 逐一执行 ZIP 容器完整性检查；Blender 同时兼容传统文件头与 Blender 5 Zstandard 压缩文件头；
- 页面在 Blender 仿真成功后开放“生成最终 5+1”，完成后原位显示六个下载入口和“下载完整套装”；
- 新增 `/api/latest-final`，刷新页面后可在预留交付槽位恢复最近一次完整成果；
- 非匹配输入返回 `NEEDS_NEW_BUILD` 并阻止复用星溪模型，避免错误模型伪装为自动生成结果。
