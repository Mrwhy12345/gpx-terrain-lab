## 1. 项目目的

把真实徒步 GPX 变成可信、可核验、可制造、可多色打印的纪念沙盘。

系统目标：

`GPX → DEM/OSM → QGIS 空间处理 → 高德人工核验 → Blender 可制造几何
→ 多色分件 3MF → Bambu Studio → 实体打印`

产品输入为一个 GPX。标准输出为：

1. 沙盘地形 3MF；
2. 底座 3MF；
3. 徒步轨迹 3MF；
4. 河流水体 3MF；
5. 可选的四件同盘 3MF；
6. 与交付版本一致的 Blender 设计预览；
7. 数据来源、参数、QA、哈希和人工复核记录。

高德只用于在线视觉核验，不作为地形、水体或纹理数据源。

## 4. 关键事实、假设与决策

### 事实

- 星溪线水体的成功来自可诊断的分层流程与原始数据持久化，不是数据源突然变好；
- 原 Overpass 失败包含依赖缺失、查询标签过窄、无正向对照和显示失败混淆；
- 高德 `10021` 是坐标转换 QPS 问题，不是 OSM 水体缺失；
- 3MF 同时存在对象网格、组件变换、Bambu 元数据和 build transform；
- Bambu Studio 的部分视图/检查可能忽略 build transform；
- “星溪徒步”使用 STHeiti TTC 时出现切片异常，Hiragino Sans GB 转网格后解决；
- 组件 Z 修正必须直接写入组件和 Bambu 元数据，不能只依赖项目级偏移。

### 当前假设

- 目标打印机为 Bambu Lab H2C，0.4 mm 喷嘴；
- 水体槽单边间隙 0.12 mm 仍需实体验证；
- 五种可见颜色由实际 AMS/喷头配置人工确认映射；
- 42 条同盘文件非流形边需要切片预览确认，目前未证明影响打印。

### 固定决策

- 原始 GPX、OSM 响应和 probe GeoJSON永不覆盖；
- 任一打印零件变化，完整套装统一升版；
- `final/` 只保留打印 3MF 和设计预览 Blender；
- 地理数据计算使用 WGS 84/局部米制坐标；
- 高德只做人工显示核验；
- 文字必须先转网格，中文使用明确覆盖中文字形的字体；
- 所有最终 3MF 必须通过组件级最低 Z=0 检查。

## 5. 失败教训与防复发

### 水体

获取、显示、核验、裁切、建模必须是独立状态。成功响应立即落盘；空结果不能直接
解释为当地没有数据。

### 坐标

Blender 场景中曾保留 GIS 大坐标。导出前必须以最终基座 Mesh 包围盒中心归一化，
不能使用对象 location 或地形对象 location 代替。

### 3MF Z 轴

曾两次出现模型位于打印床下方。以后发布必须运行：

`python3 07_Knowledge/tools/validate_bambu_3mf_z.py <final 3mf...>`

验收条件：

- 全局最低 Z 在 ±0.01 mm 内等于 0；
- 任一颜色组件不得低于打印床；
- 检查实际 3MF，而不是只检查 STL 或 Blender；
- 修正写入组件变换和 `model_settings.config`。

### 字体

不要把系统 TTC 字体对象留给切片器解释。字体在 Blender 中转为封闭网格并设置
最小笔画补偿；中文标题使用 Hiragino Sans GB。日期和里程已验证时，不要为修一个
中文字而无条件重建全部三边文字。

### Bambu CLI

命令行组合 3MF 与 STL 时可能在无界面缩略图阶段崩溃。`--min-save` 可绕开渲染，
但曾得到空对象文件。当前同盘 3MF 使用项目内封装工具生成，并由 Bambu Studio
`--info` 与 ZIP 检查反向验证。

## 9. 对外发布边界

公开代码仓库只包含：

- 可复用脚本；
- 方法、规范、架构与交接文档；
- 不含真实坐标的小型示例；
- 配置 schema 和测试。

不得公开：

- 用户 GPX 和精确路线坐标；
- OSM/高德核验截图中的私人行程信息；
- 密钥清单、API key、账号信息；
- 大体积 Blend、3MF、STL 和中间缓存；
- 未确认授权的数据或第三方资产。
