## 关键成长

### 从临时命令转向可复现脚本

水体、坐标、文字和 3MF 问题不再只留在一次操作中，而是转成可再次运行的工具。

### 从“成功就继续”转向成功即落盘

Overpass 成功后保存原始 JSON、GeoJSON 和报告，使后续工作不依赖公共 API 的
实时状态。

### 从重复探索转向低 Token 路由

总结固定参数、最短执行链、优先工具和 checkpoint，使下一条路线不必重新扫描
全部 S02 历史。

## 当前短板

- 多数脚本由固定路径和 S02 对象名连接；
- 缺少统一 `job.json` 数据契约；
- 缺少任务状态机、幂等、重试和阶段恢复；
- 缺少统一 CLI 和结构化错误码；
- 缺少自动化测试夹具和跨路线回归集；
- 尚未形成可安装的应用或 Worker。

## 下一阶段目标

1. 定义 `job.schema.json` 和样例 `job.json`；
2. 把 S02 常量提取成参数；
3. 建立 `prepare → gis → review → blender → package → qa` 状态机；
4. 每阶段支持幂等重跑和 checkpoint；
5. 实现一个命令输出四个 3MF；
6. 用第二条 GPX 验证无需修改代码。
