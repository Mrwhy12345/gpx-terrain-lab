# WEB11 反向隧道探测与自恢复

日期：2026-08-25

## 健康合同

不能只凭 SSH 进程或页面绿点判定在线。以下三项必须同时通过：

1. Neo `http://127.0.0.1:4174/api/health` 返回 2xx；
2. 上海通过本机 `127.0.0.1:4174` 能取得同一健康响应；
3. 公网 `http://124.222.145.225:4173/api/health` 返回 2xx。

## 固化命令

```bash
python3 09_WebApp/manage_tunnel.py status
python3 09_WebApp/manage_tunnel.py install
python3 09_WebApp/manage_tunnel.py repair
python3 09_WebApp/manage_tunnel.py restart
```

`install` 会在当前 macOS 用户下安装 `launchd` 服务；登录、网络恢复或 SSH 进程退出后自动重连。SSH 心跳为 20 秒，连续 3 次无响应即退出并由 `launchd` 重启。

## 故障分级

| 状态 | 含义 | 自动处理 |
|---|---|---|
| `ONLINE` | 本地、隧道落点、公网代理全部正常 | 无 |
| `LOCAL_BACKEND_OFFLINE` | Neo 4174 未启动 | 先启动后端，不盲目重连隧道 |
| `LAUNCH_AGENT_NOT_INSTALLED` | 未安装守护服务 | `repair` 自动安装 |
| `TUNNEL_DOWN` | 后端正常但上海 4174 不通 | `repair` 强制 kickstart |
| `SSH_AUTH_REQUIRED` | 密钥/腾讯云扫码阻止无人值守登录 | 必须人工完成认证或调整服务器 SSH 策略 |

## 日志

- `09_WebApp/runtime/reverse_tunnel.log`
- `09_WebApp/runtime/reverse_tunnel.error.log`

二维码认证不是心跳机制能绕过的问题。若生产连接仍周期性要求微信扫码，必须让专用 `webapp` 密钥通道真正支持 `BatchMode=yes`，否则服务只能报告 `SSH_AUTH_REQUIRED`，不能声称已自动修复。
