# GPX Terrain Lab 场景化质检体系

版本：QMS 1.0  
目标：让每次功能迭代都知道“守住了什么、改善了什么、还有什么没有证据”，而不是追求所有指标全绿。

## 一、质量原则

1. **先能打印，再能组装。** 这是面向客户交付的最低底线。
2. **工程表达、创意、便利性逐层提高。** 次要层不能掩盖基础层失败。
3. **未测试不等于通过。** 自动几何检查不能代替 Bambu Studio 切片、真机打印或实物装配。
4. **问题严重度取决于交付场景。** 同一个问题在“预览版”可能是警告，在“可装配交付版”可能是阻断。
5. **每次迭代只允许质量前进或留下明确例外。** 新功能必须跑固定回归样本并与上一基线比较。

## 二、七个质量场景

| 层级 | 场景 | 用户问题 | 最低证据 | 当前典型检查 | 对最终客户版是否必需 |
|---|---|---|---|---|---|
| Q0 | 输入与溯源 | 真的是本次上传的 GPX 吗？ | E1 | GPX 可解析、点/轨段、SHA-256、任务参数 | 是 |
| Q1 | 生成与交付完整性 | 5+1 是否齐全且能打开？ | E1 | 5×3MF、1×Blend、ZIP、文件头、哈希、非缓存任务 | 是 |
| Q2 | 可打印性 | Bambu Studio 能否正确切片并落盘打印？ | E3；封版宜 E4 | 非流形、负 Z、打印盘边界、最薄特征、颜色槽、四对象 | 是 |
| Q3 | 可组装性 | 打印后能否完整、顺利、牢固地装起来？ | E5 | 轨迹/水系强度、组件数、槽体同源、公差、压装、底座适配 | 是 |
| Q4 | 工程真实性 | 地形、水系、轨迹是否基本准确？ | E2 + 数据记录 | GPX 形状、高程、TrailPrint3D 数据源、水系筛选、坐标与关系 | 是 |
| Q5 | 创意与审美 | 标题、Logo、配色和纪念意义好吗？ | E2 + 人工评分 | 标题/Logo关联、文字位置、字体、辨识度、审美评分 | 否，产品增强 |
| Q6 | 使用便利性 | 客户是否容易完成上传、等待、预览、下载和打印？ | E1 + 用户测试 | 单一主流程、状态反馈、失败恢复、下载入口、耗时、日志 | 否，产品增强 |

基础交付链为 `Q0 → Q1 → Q2 → Q3`。其中任一层失败，都不能宣称“可打印并可组装”。Q4 决定它是不是合格的徒步地形作品；Q5、Q6 决定产品竞争力。

## 三、证据等级

| 等级 | 证据 | 能证明什么 |
|---|---|---|
| E0 | 假设/人工判断 | 只能形成待验证项 |
| E1 | 脚本静态检查 | 文件、参数、拓扑和结构符合规则 |
| E2 | Blender 同源仿真/人工视觉核验 | 装配关系、颜色、位置和外观合理 |
| E3 | Bambu Studio 打开并切片 | 切片器识别、对象层次、耗材和落盘基本正确 |
| E4 | 真机打印 | 实体能打印完成且具有基本强度 |
| E5 | 实物装配 | 公差、安装顺序、抗折和最终贴合真实通过 |

报告必须同时写状态和证据，例如 `Q2 PASS (E3)`、`Q3 NOT_TESTED (最高仅 E2)`。

## 四、问题分级（随场景变化）

### P0 阻断

阻止当前目标交付。包括：

- 任务复用了错误 GPX 或缓存成果；
- 5+1 缺件、文件打不开、3MF 不在打印盘、关键零件负 Z；
- Bambu Studio 无法正确识别或切片；
- 轨迹/水系打印即断，或实物无法安装；
- 底座不能装入奖牌框；
- 轨迹、水系、地形出现明显错位或 Z 悬空。

### P1 重大风险

当前可能可用，但很可能影响打印或装配，必须显著提示并优先处理：

- 尚未做 E4/E5 真机验证；
- 水系组件多、细颈接近下限、安装路径曲折；
- 公差仅在一条路线验证；
- 预览未覆盖最终同源几何，可能漏掉真实问题。

若真机已经证实失败，P1 自动升级为 P0。

### P2 一般问题

不影响基本打印装配，但影响工程表达或交付质量：

- 次要水系缺失、地形细节不足；
- 标题、日期、公里数位置欠佳；
- 颜色与既定规范轻微偏差；
- 下载、进度和错误提示不够清楚。

### P3 优化建议

审美提升、减件、性能、交互微调、更多机位等，不影响本阶段交付。

## 五、发布成熟度

| 等级 | 名称 | 必须满足 |
|---|---|---|
| M0 | 已生成 | Q0、Q1 自动通过 |
| M1 | 可切片候选 | Q2 至少 E3 通过 |
| M2 | 可装配候选 | Q3 数字检查通过，但尚无完整 E5 |
| M3 | 真机通过 | Q2 达 E4、Q3 达 E5；可以作为当前工程基线 |
| M4 | 工程合格 | M3 + Q4 通过，事实/假设/来源齐全 |
| M5 | 产品级 | M4 + Q5、Q6 达标，适合对外服务 |

不得跨级宣传。例如自动 QA 全绿但未打印，只能是 M1/M2，不能称 M3。

## 六、当前检查矩阵

| 检查 | 场景 | 自动/人工 | 失败等级 |
|---|---|---|---|
| GPX 解析、SHA 与任务一致 | Q0 | 自动 | P0 |
| 实时生成、禁止错用缓存 | Q0/Q1 | 自动 | P0 |
| 5×3MF + 1×Blend、ZIP、哈希 | Q1 | 自动 | P0 |
| 非流形、负 Z、打印盘、地形碎片 | Q2 | 自动 | P0 |
| 四件同盘四顶层对象、颜色槽 | Q2/Q6 | 自动 + E3 | P0 |
| 轨迹单连通、承力宽度、端点符号 | Q2/Q3 | 自动 + E4/E5 | P0/P1 |
| 水系件数目标 ≤5 | Q3 | 自动 | P1；实装失败升 P0 |
| 水系宽度、公差、同源槽 | Q3 | 自动 + E5 | P1；实装失败升 P0 |
| 三机位最终同源预览 | Q2/Q4/Q5 | 自动 + 人工 | P1/P2 |
| 地形/水系/轨迹真实性 | Q4 | 自动数据 + 人工 | P2；明显错位为 P0 |
| 标题、Logo、文字、审美 | Q5 | 人工 | P2/P3 |
| Web 主流程、进度、下载、恢复 | Q6 | 自动 + 用户测试 | P2；无法下载为 P0 |

## 七、每次迭代的质检流程

1. 记录变更影响的场景和预期，不直接修改封版成果。
2. 先跑快速静态 QA：Q0、Q1、Q2 的 E1 检查。
3. 跑三条固定 GPX 回归，并与上一份 JSON 基线比较。
4. 打开 Bambu Studio 做 E3 检查；涉及结构、公差和强度时必须补 E4/E5。
5. 分场景输出 `PASS / FAIL / NOT_TESTED / NOT_APPLICABLE`，禁止用总体 PASS 掩盖未测试项。
6. P0 立即退回；P1 进入近期计划；P2/P3 进入产品待办。
7. 真机结果反写参数基线、测试报告和成员成长档案。
8. 只有辛巴根据证据宣布成熟度升级或封版。

## 八、当前三路线的正确表述

- 三条路线 Q0、Q1 和现有自动 Q2 检查通过；用户已确认四件同盘可在 Bambu Studio 打开，形成部分 E3 证据。
- 星溪线已有轨迹、水系及奖牌框的真机经验，可作为现阶段主要 M3 基线。
- 大夫山水系 13 组件属于 Q3/P1：数字成果可交付，但装配复杂度与断裂风险较高；未发生真机失败前不作为 P0。
- 风车山本轮数字回归通过，但其完整真机打印与装配证据仍应明确写 `NOT_TESTED`，不能借用星溪线的 E5。

## 九、下一步自动化重点

1. 给每个 Web 任务生成 `quality_report.json`，按 Q0–Q6 保存状态、证据等级和问题清单。
2. 增加 Bambu Studio CLI 切片/对象/耗材检查，把 Q2 从 E1 提升到稳定 E3。
3. 建立真机反馈表，将断裂、安装力、公差、组件数与任务 ID 绑定。
4. 回归报告增加“与上一基线相比：新增、修复、退化、未变化”。
5. Web 页面按场景显示质量卡片，不再只显示一个笼统的绿色 PASS。
