# 轨迹模型｜成本与 Token 登记标准

状态：V1
生效日期：2026-09-06
适用：徒步、全程马拉松、半程马拉松及其他 GPX 纪念模型

## 1. 目的

每个 Job 从开工起持续登记成本，最终同时回答两个问题：首个合格成品投入多少，以及复打一个合格成品需要多少。Token、自然时间、人工、后台计算和打印生产分别统计，不能用其中一项代替另一项。

## 2. 固定文件

每个 Job 必须包含 `process/成本账本.md`。开工时创建，阶段结束时更新，封板时由 QA 复核。聊天中的数字不是正式记录，必须落入该文件。

## 3. 六类成本

| 类别 | 必填字段 |
|---|---|
| A. Token 与 AI | 模型、输入 Token、缓存输入 Token、输出 Token、总量、数据来源、统计起止时间、图像生成次数及费用 |
| B. 外部生成 | 工具、生成/重试次数、成功次数、积分或费用、最终采用文件 |
| C. 人工时间 | 数据准备、审美决策、Bambu 操作、装配、拍摄、发布的主动时间 |
| D. 计算时间 | GIS、Blender、几何、渲染、切片等后台运行时间及成功/失败次数 |
| E. 打印生产 | 成品、冲刷/擦料塔、支撑、失败件的克数，打印时间、电量和机器占用 |
| F. 装配发布 | 胶、磁铁、包装等辅料，装配、修图和发布工时 |

## 4. Token 强制登记

### 开工

记录 Job/当前版本、任务或会话标识、模型、带时区开始时间、输入/缓存输入/输出 Token 起始值及数据来源。不可得的字段写 `MISSING`。

### 每个阶段或模型切换

记录结束快照和差值。若一个 Job 跨多个任务或模型，逐项分行，最后求和；不能把账户共享额度的百分比变化当作本 Job Token。

### 封板

记录输入、缓存输入、输出和总量，并区分实测与估算。默认只接受平台任务明细或 API usage 为“实测”。当前环境若不提供任务级明细，写：

`MISSING｜运行环境未暴露任务级 Token；待从平台任务明细补录`

不得填0，也不得按聊天字数换算后标为精确值。确需估算时单列 `ESTIMATE`、方法和误差范围，不能混入实测合计。

## 5. 时间登记

- 自然跨度：阶段开始到结束，包含等待，仅用于排期。
- 人工时间：人实际操作和判断的时间，用于人工成本。
- 后台计算：程序、渲染和几何运算时间，用于性能优化。
- 打印机时间：预热、打印和必要占机时间，用于生产成本。
- 同一时间段可能同时发生，计算金额时必须说明是否允许并行计费，避免重复。

## 7. 最终指标

`首件总投入 = A + B + C研发 + D计费计算 + E全部试印及合格首件 + F`

`复打单件成本 = C复打操作 + D切片 + E合格打印 + F单件装配包装`

`含研发单件成本 = 复打单件成本 + 首件研发成本 ÷ 计划产量`

同时报告非金额指标：总 Token、自然交付时间、人工小时、打印机小时、总耗材和失败率。

## 8. 门禁

- 新 Job 未创建成本账本：`FAIL`，不能进入正式生产阶段。
- 阶段有调用或打印但未登记：`NEEDS_REVIEW`。
- 数据不可得且已如实写 `MISSING`：允许继续制作，但封板总结必须披露。
- 项目承诺“完整成本核算”而 Token 或实际打印数据仍缺失：不得宣布成本统计完成。
